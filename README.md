# A-share Quant

个人 A 股量化研究与选股项目，使用 Python + AKShare 获取公开市场数据。

> 当前阶段：双策略日线初筛已加入回调真实性、底部深跌惩罚、ATR波动率和一手预算过滤；等待 GitHub Actions 回归测试。14:30 分钟线确认、历史回测、推荐复盘、交易日历和自动通知尚未完成。

## 当前已实现

### 数据采集
- 获取沪深京 A 股实时行情快照；数据源按东方财富 → 新浪 → 腾讯自动降级。腾讯实时行情由公开 qt.gtimg.cn 接口批量获取，证券代码列表在该备用路径下由 BaoStock `query_stock_basic` 提供；若 BaoStock 返回的证券范围不完整，系统会按覆盖率门槛拒绝将其当作完整市场扫描。
- 获取行业板块和概念板块概览；东方财富板块接口不可用时切换新浪板块数据。
- 历史日线优先使用东方财富/腾讯/新浪 AKShare 接口；以上均失败时，使用 BaoStock 0.9.4+ 的 `query_history_k_data_plus` 作为最后备用源，并对每只股票计算技术指标。
- 默认详细历史K线扫描池为120只，按快照成交额排序选取；这不是对全市场5,000多只股票逐只计算完整指标。
- 当日成交额仅用于有限历史请求池的排序，不作为近20日流动性硬门槛；真正的流动性门槛使用已完成日K线的20日平均成交额计算。
- 所有均线、历史高低点和成交量指标只使用当前交易日前已完成的日K线；当前价和当日涨跌幅来自单独行情快照。

### 双策略并行
系统独立计算两种策略分数和B/C档，不强制两类策略各占固定名额，最终按信号质量排序。

#### 策略A：趋势回调低吸
- 近20日涨幅为正、MA20不明显转弱、现价大致守住MA20区域。
- 60日涨幅只作为加分项，不再作为一票否决条件。
- 优先寻找前期有一定上涨、近期回调、回调缩量、靠近均线支撑的股票。
- 当日涨幅过大或急跌时不作为买入候选。

#### 策略B：阶段性底部反弹
- 允许近20日或60日涨幅为负。
- 要求此前存在阶段性调整，股价靠近20日或60日区间低位。
- 当前价格必须守住20日区间低位附近，且出现止跌、反弹或成交量企稳信号。
- 持续创新低、明显跌破阶段低位、没有止跌迹象的股票不得进入B档。
- 近20日跌幅不高于-25%、60日高点回撤不低于-50%、MA20斜率不低于-8%等中期风险条件用于阻止深度下跌股进入B档；触发严重下跌惩罚时最多保留观察级别。
- B档还需站回MA5附近、出现MA5企稳/短期反弹，并通过ATR及100股一手预算检查。

### 档位与买入约束
- B档：至少一类策略达到较好的日线观察条件。
- C档：部分条件符合，仍需等待确认；可包含一手预算暂不可承受或中期跌幅仍偏大的观察对象。
- 排序先看档位，再优先可按100股整数手买入且ATR处于适宜区间的候选，最后比较策略评分和流动性。
- N档：两类策略均未达到观察门槛。
- 没有14:25～14:30分钟线确认时，所有候选的 buyable 均为 false，不生成精确买入价或保证成交的止盈价。
- 日线B档不等于可直接买入；分钟线、实时价格和风险退出位仍需确认。

## 资金与风险规则

默认按账户资金不超过10,000元计算：
- 至少保留30%现金。
- 最多同时持有2只。
- 单只股票预算上限设为10,000元，但账户总资金按10,000元、至少保留30%现金计算，故单只实际可用上限为7,000元。
- 只持有1只时，最多可使用7,000元；同时持有2只且均分投资资金时，每只约3,500元。系统同时输出单只持仓与双持仓两种预算场景。
- 按A股100股整数手计算可买数量；若一手超过当前场景的可用预算则标记为不可负担。
- 单笔计划最大亏损约为该笔买入金额的5%，不是账户总资金的5%。
- 3%～5%为止盈观察目标。
- 单笔持仓最迟第10个交易日复核退出。
- 5%风险值不是保证止损成交价；跳空、滑点、流动性和交易费用可能导致实际损失更大。

JSON结果会在 risk_management 字段中披露资金规则；每只候选的 risk_plan 字段会给出按100股整数手估算的预算、股数、计划风险金额和目标收益金额。估算不包含交易费用。

## 单独验证腾讯备用行情源

主扫描优先使用东方财富，限流/失败后尝试新浪，只有前两者都不可用时才会进入腾讯实时行情 + BaoStock 股票代码列表的备用路径。因此，普通主扫描成功不代表腾讯备用路径已经被实际调用。

要单独验证腾讯与 BaoStock：
1. 打开仓库 Actions。
2. 选择 **Tencent and BaoStock fallback smoke test**。
3. 点击 Run workflow。
4. `max_symbols=0` 表示检查 BaoStock 返回的全部在市 A 股；建议首次保持默认值。
5. `min_coverage=0.60` 表示腾讯至少返回60%的证券报价，且报价必须包含有效价格和至少一个报价时间。
6. 运行结束后下载 `tencent-baostock-smoke-test` Artifact，查看 `tencent_smoke_test.json` 中的覆盖率、报价时间和样例。

腾讯行情字段按公开接口位置解析：现价3、昨收4、时间30、涨跌幅32、成交额37（万元）、换手率38、涨停价47、跌停价48、量比49。量比字段不是47；代码和单元测试已按49修正。

这项测试会直接请求腾讯，不依赖东方财富或新浪是否故障。测试通过后，才算验证了第三数据源的实际可用性。腾讯公开接口仍没有商业 SLA，覆盖率和报价时间应每次运行检查。

## 运行全市场扫描

1. 打开仓库 Actions 页面。
2. 选择 A-share full-market scan。
3. 点击 Run workflow。
4. 默认参数：max_history_stocks=120、min_amount_cny=100000000、delay_seconds=1.2。
5. 等待运行结束，在 Artifacts 下载 a-share-market-scan。

本地运行需要 Python 3.11：
- python -m pip install -r requirements.txt
- python -m unittest discover -s tests -v
- python -m src.market_scan --max-history-stocks 120 --min-amount-cny 100000000 --delay-seconds 1.2

## 输出文件
- data/market_scan.json：市场概览、数据覆盖、两种策略分数、B/C/N档、风险预算和数据限制。
- data/candidates.csv：逐只股票的指标和策略结果。
- GitHub Actions Artifact 保留30天。

## 数据限制与后续开发
- 全市场快照覆盖与详细历史K线覆盖不同；技术指标目前只对默认120只历史扫描池计算。
- 新浪实时快照的采集时间不是交易所逐笔报价时间；腾讯备用源会记录其返回的单股行情时间字段。
- 腾讯 `qt.gtimg.cn` 为公开非正式接口，没有官方 SLA；BaoStock 为独立数据服务，也可能出现网络/访问限制。多源降级只能提高可用性，不能保证永不故障。
- 腾讯实时行情字段按公开接口约定解析，成交额字段以万元为单位换算为元；上线后应持续监控报价时间、覆盖率和与主源的偏差。
- 当前没有14:30分钟线确认、财务公告核验、历史推荐跟踪、10日复盘和回测。
- 当前工作流仍需手动触发；交易日历、A股交易日14:30自动运行和ChatGPT通知尚未启用。
- 行业/概念板块只作为市场环境信息，不直接证明某只股票符合策略。

后续路线：
1. 验收双策略回归测试和行情扫描（本轮新增腾讯报价解析和代码映射测试）。

3. 建立历史回测，比较买入后第3/5/7/10个交易日收益、止盈触达率和最大不利波动。
4. 建立推荐快照与10个交易日跟踪复盘。

## 多数据源故障注入测试

通过 GitHub Actions 中的 **Multi-source failover fault-injection test** 工作流，可主动模拟东方财富、新浪及其他 AKShare 实时快照接口同时失败，随后调用真实腾讯实时行情 + BaoStock 股票列表；同一任务还会模拟 AKShare 历史K线接口失败，再真实请求 BaoStock 历史日K。工作流生成 `multi-source-failover-report` Artifact，记录实际接管数据源、覆盖数量、报价时间和历史K线数量。此测试会对第三方服务发起真实网络请求，耗时可能达到数分钟；它不代表第三方接口具有 SLA。
