# A-share Quant

个人 A 股量化研究与选股项目，使用 Python + AKShare 获取公开市场数据。

> 当前阶段：六策略日线/行情快照初筛已实现，详细历史K线默认扫描300只；工作流已配置北京时间工作日14:00自动扫描，并在成功后将机器可读结果发布到公开仓库，供ChatGPT每日14:30任务读取。首次定时运行仍需验收。14:25～14:30分钟线确认、历史回测和完整自动复盘仍在后续开发。

## 当前已实现

### 数据采集
- 获取沪深京 A 股实时行情快照；数据源按东方财富 → 新浪 → 腾讯自动降级。若东方财富/新浪快照缺少量比、换手率等字段，会对全市场证券代码批量请求腾讯行情，只补齐主源缺失的量比、换手率、成交量和成交额，不覆盖主源价格与涨跌幅；逐股记录腾讯报价时间及字段来源。腾讯实时行情由公开 qt.gtimg.cn 接口批量获取，证券代码列表在独立备用路径下由 BaoStock `query_stock_basic` 提供；若 BaoStock 返回的证券范围不完整，系统会按覆盖率门槛拒绝将其当作完整市场扫描。
- 获取行业板块和概念板块概览；东方财富板块接口不可用时切换新浪板块数据。
- 历史日线优先使用东方财富/腾讯/新浪 AKShare 接口；以上均失败时，使用 BaoStock 0.9.4+ 的 `query_history_k_data_plus` 作为最后备用源，并对每只股票计算技术指标。
- 默认详细历史K线扫描池扩大到300只，按流动性、趋势、盘中动量、弱势反弹和活跃度五类快照信号分桶，再跨沪深京板块交错去重；这不是对全市场5,000多只股票逐只计算完整指标。
- 当日成交额仅用于有限历史请求池的排序，不作为近20日流动性硬门槛；真正的流动性门槛使用已完成日K线的20日平均成交额计算。
- 所有均线、历史高低点和日线成交量指标只使用当前交易日前已完成的日K线；当前价和当日涨跌幅来自主行情快照。量比/换手率可由腾讯补充，且保留逐股报价时间和字段来源。

### 六类短线机会并行
系统独立计算六种策略分数和B/C档，不强制每类策略占固定名额，最终按信号质量排序。默认历史K线扫描池扩大为300只，近20日平均成交额门槛默认由1亿元放宽至5,000万元。放宽意味着候选范围更广，不代表低流动性股票可以直接买入。

#### 策略A：趋势回调低吸
- 近20日涨幅为正、MA20不明显转弱、现价大致守住MA20区域。
- 60日涨幅只作为加分项，不再作为一票否决条件。
- 优先寻找前期有一定上涨、近期回调、回调缩量、靠近均线支撑的股票。
- 当日涨幅过大或急跌时不作为买入候选。

#### 策略B：阶段性底部反弹
- 允许近20日或60日涨幅为负。
- 要求此前存在阶段性调整，股价靠近20日或60日区间低位。
- 当前价格必须守住20日区间低位附近，且出现止跌、反弹或成交量企稳信号。
- 持续创新低、明显跌破阶段低位、没有止跌迹象的股票不得进入B档。
- 近20日跌幅不高于-25%、60日高点回撤不低于-50%、MA20斜率不低于-8%等中期风险条件用于阻止深度下跌股进入B档；触发严重下跌惩罚时最多保留观察级别。
- B档还需站回MA5附近、出现MA5企稳/短期反弹，并通过ATR及100股一手预算检查。


#### 策略C：平台突破启动
- 比较现价与此前已完成的20日最高价，关注刚刚突破或接近平台上沿的股票。
- 要求当日涨幅不过热、量比和近20日平均成交额提供支持。
- 突破超过20日高点不代表必然有效，仍需防范假突破。

#### 策略D：强势趋势延续
- 关注近5/10日已有正向动量、价格处于MA10/MA20上方、当日继续温和走强的股票。
- 量比过低说明动能不足，涨幅过大则降低排序，避免追高。

#### 策略E：隔日冲高观察
- 重点看当日适中涨幅、量比活跃、近3/5日动量为正、价格守住MA5附近且未明显偏离MA5的股票。
- 这是“次日可能有冲高空间”的观察模型，不是对次日收益的承诺；A股T+1下当日买入不能当日卖出。
- 当前只有实时快照与日线，尚无14:25～14:30分钟结构/尾盘资金确认，因此不能标记为可执行买点。

#### 策略F：短线超跌反弹
- 关注靠近20/60日低位、较近5日低点出现反弹、当日温和走强且量能改善的股票。
- 深跌股只有出现止跌和反弹证据才会进入观察，不因跌得多就自动视为便宜。

### 档位与买入约束
- B档：至少一类策略达到较好的日线观察条件。
- C档：部分条件符合，仍需等待确认；可包含一手预算暂不可承受或中期跌幅仍偏大的观察对象。
- 排序先看档位，再优先可按100股整数手买入且ATR处于适宜区间的候选，最后比较策略评分和流动性。
- N档：六类策略均未达到观察门槛。
- 没有14:25～14:30分钟线确认时，所有候选的 buyable 均为 false，不生成精确买入价或保证成交的止盈价。
- 日线B档不等于可直接买入；分钟线、实时价格和风险退出位仍需确认。

## 新闻与舆情分析

扫描流程在技术候选排序完成后，独立运行新闻采集，不改变现有六种技术策略的评分或排序。当前免费数据源通过 AKShare 调用：
- 东方财富全球财经快讯：`stock_info_global_em`
- 新浪全球财经快讯：`stock_info_global_sina`
- 财联社全球财经快讯：`stock_info_global_cls`
- 同花顺全球财经快讯：`stock_info_global_ths`
- 富途快讯：`stock_info_global_futu`
- 财新财经内容精选：`stock_news_main_cx`
- 候选个股新闻：`stock_news_em`
- 候选公司公告：`stock_zh_a_disclosure_report_cninfo`（巨潮资讯）

为控制免费接口访问频率，当前仅对技术排序前20只候选逐只查询个股新闻和公告；未查询的候选明确标记为 `not_scanned`，不得将“未查询”解释成“没有负面新闻”。市场快讯源逐一隔离调用，单个来源失败不会使行情扫描整体失败。

新闻采集范围以最近48小时为主。只有能解析发布时间且确认为最近48小时的新闻，才计入近期舆情摘要；无可解析发布时间的新闻保留来源信息但不计入近期情绪统计。系统记录原始标题、内容摘要、发布时间、来源、链接、事件类别、关键词命中和风险词。

当前情绪分类采用透明的中文关键词规则（正面、负面、混合、未分类），并列出触发词和事件类别。该方法是初步筛查，不具备完整语义理解能力，可能受到否定语境、标题党、转载重复、传闻和上下文影响。重大利好/利空必须回到公告原文或交易所/公司披露核实。

重要纪律：
- 新闻舆情先作为独立风险/背景维度展示，不直接加减六种技术策略分数，也不自动生成买卖信号。
- “利好”不等于股价必涨；需要结合发布时间、股价此前走势、成交量、板块反应和市场是否已提前定价。
- “利空风险词”只触发人工复核提示，不等同于已确认违规或基本面恶化。
- 免费公开网页接口没有商业 SLA，可能限流、延迟、字段变化或不可用；每次运行都输出各数据源状态和错误。
- 个股新闻与公告仅覆盖技术排名前20只股票；其余股票的舆情覆盖不完整，最终推荐前应针对入选股票再次核验。

输出：
- `data/news_sentiment.json`：完整新闻与舆情结果。
- `market_scan.json` 的 `news_data`：嵌入新闻采集状态和摘要。
- `candidates.csv`：增加 `news_sentiment_label`、`news_sentiment_score`、`news_risk_alert`、`news_scanned` 等字段。
- `scan-results/latest/news_sentiment.json`：供 ChatGPT 每日任务读取的公开接口文件。

## 资金与风险规则

默认按账户资金不超过10,000元计算：
- 至少保留30%现金。
- 最多同时持有2只。
- 单只股票预算上限设为10,000元，但账户总资金按10,000元、至少保留30%现金计算，故单只实际可用上限为7,000元。
- 只持有1只时，最多可使用7,000元；同时持有2只且均分投资资金时，每只约3,500元。系统同时输出单只持仓与双持仓两种预算场景。
- 按A股100股整数手计算可买数量；若一手超过当前场景的可用预算则标记为不可负担。
- 单笔计划最大亏损约为该笔买入金额的5%，不是账户总资金的5%。
- 3%～5%为止盈观察目标。
- 单笔持仓最迟第10个交易日复核退出。
- 5%风险值不是保证止损成交价；跳空、滑点、流动性和交易费用可能导致实际损失更大。

JSON结果会在 risk_management 字段中披露资金规则；每只候选的 risk_plan 字段会给出按100股整数手估算的预算、股数、计划风险金额和目标收益金额。估算不包含交易费用。

## 实时行情多源交叉验证

使用 GitHub Actions 的 **Live quote cross-source validation** 工作流，独立请求东方财富、新浪和腾讯实时行情，对相同股票进行价格、涨跌幅和成交额交叉比较。东方财富/新浪不可用时，会尝试 AKShare 通用快照接口；若 AKShare 实时快照全部失败，则用 BaoStock 仅获取股票代码列表，再请求腾讯行情并生成“数据源不足”的诊断报告。此时报告状态为 `insufficient_comparisons`，Actions 任务可以正常结束，但绝不代表行情准确性已通过验证。

操作：
1. 打开仓库 Actions。
2. 选择 **Live quote cross-source validation**。
3. 点击 Run workflow，保持默认 `sample_size=150`。
4. 建议在A股连续竞价时段运行，最好接近你实际使用的14:30；非交易时段只比较静态报价，不评价实时新鲜度。
5. 运行后下载 `live-quote-crosscheck` Artifact。

报告文件：
- `quote_crosscheck.json`：数据源可用性、采集时间、腾讯报价时间新鲜度和每组对比汇总。
- `quote_crosscheck_pairs.csv`：东方财富/新浪/腾讯两两比较统计。
- `quote_crosscheck_details.csv`：逐股票的价格、涨跌幅、成交额偏差和异常排序。

价格偏差按两来源价格均值计算：不超过0.20%标为正常，0.20%～0.50%标为需关注，超过0.50%标为异常。这些是项目内部排查阈值，不是交易所或数据商的正式误差承诺。成交额偏差只作诊断，不作为行情准确性单一判据；不同接口采集时间不同，快速波动时价格差异可能来自报价时点。

AKShare东方财富/新浪快照不提供可靠的逐证券交易所时间戳，因此只记录本机采集起止时间；腾讯逐证券时间戳会额外计算报价年龄。处于A股连续竞价钟点区间时，腾讯样本报价95分位年龄超过180秒会标记为 stale_or_unverifiable；非连续竞价钟点区间不做新鲜度判定。当前检查仅识别星期与时钟区间，不核验交易所节假日，因此节假日需人工确认。若可用报价源不足两家，报告会保留源状态和错误信息，但不会计算或宣称来源一致性。

## 单独验证腾讯备用行情源

主扫描优先使用东方财富，限流/失败后尝试新浪，只有前两者都不可用时才会进入腾讯实时行情 + BaoStock 股票代码列表的备用路径。因此，普通主扫描成功不代表腾讯备用路径已经被实际调用。

要单独验证腾讯与 BaoStock：
1. 打开仓库 Actions。
2. 选择 **Tencent and BaoStock fallback smoke test**。
3. 点击 Run workflow。
4. `max_symbols=0` 表示检查 BaoStock 返回的全部在市 A 股；建议首次保持默认值。
5. `min_coverage=0.60` 表示腾讯至少返回60%的证券报价，且报价必须包含有效价格和至少一个报价时间。
6. 运行结束后下载 `tencent-baostock-smoke-test` Artifact，查看 `tencent_smoke_test.json` 中的覆盖率、报价时间和样例。

腾讯行情字段按公开接口位置解析：现价3、昨收4、时间30、涨跌幅32、成交额37（万元）、换手率38、涨停价47、跌停价48、量比49。量比字段不是47；代码和单元测试已按49修正。

这项测试会直接请求腾讯，不依赖东方财富或新浪是否故障。测试通过后，才算验证了第三数据源的实际可用性。腾讯公开接口仍没有商业 SLA，覆盖率和报价时间应每次运行检查。

## 运行全市场扫描

1. 打开仓库 Actions 页面。
2. 选择 A-share full-market scan。
3. 点击 Run workflow。
4. 默认参数：max_history_stocks=300、min_amount_cny=50000000、delay_seconds=1.2。
5. 等待运行结束，在 Artifacts 下载 a-share-market-scan。

当主行情源缺少量比或换手率时，主扫描会尝试腾讯补充全市场对应字段；若补充失败，`market_data.tencent_quote_enrichment` 会记录失败/覆盖率，缺失指标保持为空，不会用估算值替代。主源价格和涨跌幅始终优先保留，避免混用不同时点的价格数据。

本地运行需要 Python 3.11：
- python -m pip install -r requirements.txt
- python -m unittest discover -s tests -v
- python -m src.market_scan --max-history-stocks 300 --min-amount-cny 50000000 --delay-seconds 1.2

## 输出文件
- data/market_scan.json：市场概览、数据覆盖、六种策略分数、B/C/N档、风险预算、腾讯补充行情覆盖率/字段来源和数据限制。
- data/candidates.csv：逐只股票的指标和策略结果（含新闻舆情摘要字段）。
- data/news_sentiment.json：多源市场新闻、个股新闻/公告、发布时间、链接、关键词分类和风险提示。
- GitHub Actions Artifact 保留30天。

## ChatGPT每日选股数据接口

全市场扫描成功后，GitHub Actions 会将当次结果发布到仓库 `scan-results/latest/`，供ChatGPT每日14:30任务直接读取，无需下载Actions Artifact：
- [manifest.json](https://raw.githubusercontent.com/wukenaihe1213/a-share-quant/main/scan-results/latest/manifest.json)：扫描日期、运行编号、状态和覆盖数量。
- [market_scan.json](https://raw.githubusercontent.com/wukenaihe1213/a-share-quant/main/scan-results/latest/market_scan.json)：市场概况、数据源、六策略评分和前50名候选。
- [candidates.csv](https://raw.githubusercontent.com/wukenaihe1213/a-share-quant/main/scan-results/latest/candidates.csv)：逐只股票的技术指标和策略结果。
- [news_sentiment.json](https://raw.githubusercontent.com/wukenaihe1213/a-share-quant/main/scan-results/latest/news_sentiment.json)：多源市场快讯、候选个股新闻、巨潮资讯公告、关键词舆情摘要和数据源状态。

ChatGPT任务必须核验 `manifest.json` 与 `market_scan.json` 的 `collected_at`，仅使用北京时间当日的成功扫描结果；不得将前一交易日的文件当作当天行情。扫描报价时间与14:30有间隔时，必须披露实际采集时间，并尽可能重新核验候选股最新价格。若文件缺失、扫描失败或数据过期，必须明确说明GitHub数据链路未成功，不得伪造实时指标或买入价。

## 数据限制与后续开发
- 全市场快照覆盖与详细历史K线覆盖不同；技术指标目前只对默认300只历史扫描池计算。
- 新浪实时快照的采集时间不是交易所逐笔报价时间；腾讯备用源会记录其返回的单股行情时间字段。
- 腾讯 `qt.gtimg.cn` 为公开非正式接口，没有官方 SLA；BaoStock 为独立数据服务，也可能出现网络/访问限制。多源降级只能提高可用性，不能保证永不故障。
- 腾讯实时行情字段按公开接口约定解析，成交额字段以万元为单位换算为元；上线后应持续监控报价时间、覆盖率和与主源的偏差。
- 当前没有14:25～14:30分钟线确认、财务公告核验、历史推荐跟踪、10日复盘和回测。六类日线/快照评分只能用于候选排序，不能证明“今天买、明天卖”一定盈利。
- 全市场扫描工作流已同时支持手动触发和工作日14:00（北京时间）定时触发；GitHub cron按周一至周五运行，不自行识别法定节假日，ChatGPT每日任务必须另行核验A股交易日并拒绝使用非交易日或过期结果。
- 行业/概念板块只作为市场环境信息，不直接证明某只股票符合策略。

后续路线：
1. 验收六策略回归测试和行情扫描（本轮新增腾讯补充行情字段合并、来源标记和缺失值保留测试）。
2. 接入14:25～14:30分钟线，确认止跌和二次启动。
3. 建立历史回测，比较买入后第3/5/7/10个交易日收益、止盈触达率和最大不利波动。
4. 建立推荐快照与10个交易日跟踪复盘。
